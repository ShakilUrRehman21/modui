# ModUI — Workspace Memory & Development Directives

## 1. Core Mandate: Build Genuinely Useful Components
- Every candidate component proposed or built for ModUI **must possess deep, immediate real-world utility** for production web applications, SaaS dashboards, developer tools, or commercial landing pages.
- **Do not propose purely decorative or abstract visual novelties** (e.g., abstract lidar meshes, holographic spectrum analyzers).
- Every primitive must solve a concrete, everyday interaction need while maintaining ModUI's signature craft: tactile physical motion, standard CSS properties, zero external runtime style dependencies, and optional Web Audio haptics.

## 3. Architecture & Project Constraints
- **Zero External Style Dependencies**: Pure standard CSS custom properties and native React 19 APIs. No Tailwind classes inside component source code.
- **Zero External Audio Assets**: All acoustic haptics must use native Web Audio API oscillators.
- **Naming Rule**: NEVER mention or use "ModUI 2.0" anywhere.
- **Git Push Rule**: Never push to remote repository without explicit user command ("push").
